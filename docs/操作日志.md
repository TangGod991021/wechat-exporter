### 修复：导出缺少大量历史消息（消息分库未合并）

- 用户反馈微信 4.2.0.51 导出只有较新消息，客户端里仍能看到完整历史
- 根因：微信 4.x 会把同一会话的消息表滚动写入 `message_0.db`、`message_1.db` … 多个分库；
  `ChatStore.table_map` 用 `mapping[name] = db` 覆盖，只保留最后一个分库，导出/预览/计数都只读这一份
- 本机微信安装可复现证据：某账号 `message_0.db` 最后写入 2026-11-02（当前），
  `message_1.db` 最后写入 2026-05-09（历史），两个分库同时存在
- 修复：
  - `table_map` 改为「表名 → 分库列表」，`find_tables` 返回全部命中分库
  - `messages()` 逐库查询后合并，按 `(create_time, sort_seq, local_id)` 排序、按完整行去重；
    分页新增 `before_sort` 游标（毫秒级 `sort_seq`），同一秒消息不再丢
  - `message_count` / `table_counts` 跨分库累加；会话数量缓存升级 v2 自动重算
  - `message_dbs` 与 `chat_db_rels` 纳入 `biz_message_*.db`，公众号消息可导出
  - `/api/core`、`/api/prepare` 明确提示「消息库缺少密钥 / 解密失败」，第 2 步新增「重新提取密钥」

### 修复双击 exe 无反应

- 现象：双击 `dist\微信聊天记录导出\微信聊天记录导出.exe`，无窗口、无报错，约 20 秒后进程消失；命令行带输出重定向启动则正常
- 根因：PyInstaller 窗口模式（`console=False`）下 `sys.stdout/stderr` 为 `None`；uvicorn 初始化日志时调用 `sys.stdout.isatty()` 抛异常，异常发生在后台线程中被吞掉，`wait_server` 超时后进程静默退出
- 修复：`app/main.py` 启动时用 `devnull` 兜底标准输出/错误流；uvicorn 线程异常会被捕获并合并进启动错误；启动失败时写入 exe 同级的 `启动错误.log` 并弹出错误对话框
- 重新打包并验证：模拟资源管理器启动（`Start-Process` 无输出重定向）窗口正常显示、服务正常监听、24 秒后仍在运行、首页返回 HTTP 200
- 补充 README / USAGE 的「双击无反应」排查说明
